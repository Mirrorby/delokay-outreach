# Delokay: тест 10 первых сообщений в Telegram

Один контакт за короткий запуск GitHub Actions, от личного аккаунта через
Telethon. Без ИИ и дальнейших автоматических ответов. Railway, Cloudflare
и постоянно работающий компьютер не нужны.

## Управление

Рабочий workflow: `Mirrorby/instagram-store-finder` → Actions →
**Delokay first message**. Он использует сохранённые там секреты и закреплённый
коммит кода из этого репозитория. Данные авторизации не копируются в новый
репозиторий. Запуски сериализованы со сборщиком Telegram.

В существующей Google-таблице:

- **Рассылка — сообщения**: впишите точные 10 текстов в B2:B11, номера 1–10
  уже стоят в A2:A11. Все 10 обязательны, пустые/повторные номера блокируют
  отправку. Тексты читаются перед каждой попыткой.
- **Рассылка — настройки**: B2 = `Да` включает отправку; `Нет` ставит на паузу.
  Пока тексты не заполнены, оставьте `Нет`.
- **Рассылка — журнал**: зафиксированы 204 получателя из Telegram-листа
  `YARDSALE.MD Chat`. Новые строки сборщика не добавляются в этот тест.
  Состояние, номер варианта и точный отправленный текст сохраняются для
  сравнения результатов. Доставка здесь означает успешное принятие запроса
  Telegram, а не прочтение сообщения.

После заполнения B2:B11 установите в настройках B2 = `Да`.
Проверка запускается каждые 10 минут в окне 09:00–20:00 по Минску;
между попытками не меньше 10 минут, максимум 10 попыток в день.
GitHub может задерживать или пропускать запуски. Стандартные Linux runners
публичных репозиториев бесплатны по правилам GitHub.

Режимы ручного workflow: `check` проверяет таблицу и сессию без отправок;
`test` отправляет следующий вариант только в «Избранное»; `enable`/`pause`
включают и выключают расписание; `send` обрабатывает одного получателя;
`setup` создаёт отсутствующие служебные листы. Непустой журнал `setup` не
сбрасывает и не дополняет.

## Порядок вариантов и получателей

Варианты идут 1→2→…→10→1. Успешная отправка продвигает номер. Пропуск или
ошибка его не продвигают. При 204 успешных отправках варианты 1–4 получат
по 21 отправке, остальные — по 20. Дальнейших автоответов нет.

Только контакты фиксированного списка, с username, исходным статусом
`Новый`/пусто и без даты первого сообщения. Instagram не обрабатывается.
Проверяются исходный Telegram ID, отсутствие прежней переписки, бот/удалённый
аккаунт. Чтобы исключить контакт, измените его статус в исходном листе.
Скрипт не заменяет исключённых участников новыми людьми. По исчерпании
доступной очереди отправка выключается.

До отправки фиксируется попытка, а исходная строка помечается `Написал` с
датой. Неизвестный результат никогда не повторяется автоматически: проверьте
Telegram и журнал. Статус `Написал` в источнике при ошибке не подтверждает
отправку; подтверждённая отправка в журнале — `Отправлено`.

Не сортируйте и не перемещайте строки во время отправки. Не запускайте другую
рассылку тем же аккаунтом одновременно. При FloodWait, PeerFlood, блокировке или отзыве сессии отправка выключается
до ручного включения. Рабочий аккаунт отправляет отчёт на личный ID из
настроек: причина, код ошибки, время, срок (если Telegram его сообщил),
контакт, вариант, число отправок и ссылка на запуск. Полный отчёт также
сохраняется в настройках. Если сам рабочий аккаунт не может писать или
авторизоваться, доставка уведомления не гарантируется: ошибка сохраняется
в таблице. Небольшой лимит не гарантирует отсутствия ограничений.

Режим `notify-test` проверяет уведомление на личный аккаунт без отправки
клиентам. Служебный access hash получателя сохраняется только в закрытой
таблице, чтобы уведомление не требовало поиска диалога при ограничении.

Контакты, тексты, Telegram-сессия и Google-ключ не публикуются в Git, Actions
Artifacts или логах. Секреты: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
`TELEGRAM_SESSION`, `GOOGLE_SERVICE_ACCOUNT_JSON`, опционально `GOOGLE_SHEET_ID`.
